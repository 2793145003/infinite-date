# 种植 + 料理系统设计（「共享菜园」）

> 状态：**设计中，未动代码**（离线实测已跑，见第十四节）。已定项来自星落口述，其余标"待拍板"。
> 定位：恋爱向的「生活素材系统」——你种菜、做菜，产出不是数值，而是**角色能说、能晒、能记住的东西**。
> 标志性瞬间：沈星回被偷了菜，发一条朋友圈「不知道为什么，我种的菜好像越来越少了……」

---

## 一、已定（星落拍板，不再讨论）

1. **独立功能、独立可测**：自成模块与自己的表，不掺进约会/短信链路也能单独跑通、单独测。
2. **入口先放「设置 → 更多功能 → 实验功能」**，与「互动小说」「衍生世界」并列第三格，名字叫 **🌱 共享菜园**。
3. **玩家有自己的农场**；**只有男主（主线角色）也有农场**——位面任务的崽（`plane_characters`）**不在范围内**。
4. **种子来源**：初始赠送 + 探索地图掉落 + 收菜留种 + 偷菜概率获得。
5. **按现实时间生长，每种作物时长不同**，目的是让玩家隔一阵就回来看看（作物表见第五节，已定稿）。
6. **只允许玩家偷男主的菜**；**没有任何人会偷玩家的菜**（玩家侧不做失窃机制）。
7. **被偷的后果**：**只写进记忆**（不进数值、不发秒回），**按行程概率**让他自己发朋友圈；只让他知道「我的收成变少了」，**不告诉他是玩家偷的**——他可以怀疑，也可以栽赃（栽赃第三方，或半真半假地暗示玩家）。
8. **成熟后不理它没有任何损失**：不枯死、不扣产（这不是农场游戏）。
9. **料理是独立玩法系统，复用衍生世界的二消（布偶餐厅式）引擎**；二消引擎的块定义要**参数化或重做**（原先写死了修仙五行）。
10. **作物可以乱编、可以奇幻向**（星光果这种），每个男主还可以有**专属作物**。
11. 料理文案与男主反应**必须先离线实测**（见第十四节，已跑完第一轮）。

## 二、三条铁律（继续有效）

1. **不做农场游戏的管理压力**：不枯死、不虫害、不上限、不氪金加速、不做每日签到式赎罪感。
2. **每个产出都必须能变成角色的话**：作物有变化 → 必须落成一条 ta 能说出口的东西（朋友圈 / 记忆），否则不做这个功能。
3. **不引入数值好感**：主线 `relationships` 只有 `player_description` 文本 + chronicles + 向量记忆 + 心绪。农场产出统一走 `storeEmbedding` / `player_facts` / 心绪（且**只在玩家在场的事件**里由 LLM 评估，不凭空赋值、不自动衰减）。
4. **成本沿用衍生世界的范式**：背景层（作物生长、男主照看院子）是纯规则演化，0 token；只有「ta 要说话了」才调 LLM。

## 三、核心循环

```
种子 ──► 播种 ──► 生长（现实时间，离线也在长）──► 成熟 ──► 收获（不摘也不会坏）
 ▲                                                          │
 │ 种子来源：                                                ├─► 食材 ──► 料理（二消）──► 菜品 ──► 送出/晒图
 │ ① 初始赠送 ② 探索地图 ③ 收菜留种 ④ 偷菜                   └─► 背包
 │
 └─► 去男主的院子偷 ──► 他的收成变少 ──► 写进记忆 ──► 按行程概率发朋友圈（不指名玩家）
```

一句话版本：**你偷他的菜，他念叨你；你给他做菜，他记着。**

## 五、作物表（定稿）与数据模型

### 作物（现实时间，越长越稀有）

| 作物 | 时长 | 收获 | 备注 |
|---|---|---|---|
| 小葱 | 2h | 3 | 起步作物，人人会种 |
| 晨露菜 | 3h | 2 | |
| 番茄 | 4h | 3 | |
| 黄瓜 | 5h | 3 | |
| 烈火椒 | 6h | 2 | |
| 草莓 | 8h | 4 | |
| 云顶米 | 12h | 5 | |
| 南瓜 | 12h | 2 | 一颗就够做一锅 |
| 葡萄 | 16h | 6 | 藤上多 |
| 山参 | 24h | 1 | 稀有，适合送人 |
| **星光果**（奇幻） | 20h | 2 | 只长在特定院子的稀有作物（草案，见下） |

**专属作物（提案，待拍板）**：每个男主一种，从他的 `drive` / 性格 / evol 推（例：沈星回的 evol 是"光" → 星光果）。
**专属作物的种子只能从他的院子偷、或他送你**；用专属作物才能做出"他最爱的那道菜" → **偷菜这件事第一次有了动机**，而且闭环很甜：你偷他的东西、做成他爱吃的菜端给他，他一句「这味道我认识……你哪来的？」。这条要是成立，偷菜就从"手贱"变成"故意的甜"。

### 掉率（草案）

- 探索地图：命中那条既有物品掉落时，额外 **35%** 掉一颗种子（品种按地点/时段随机）
- 收菜留种：**30%**
- 偷菜附赠：**25%**（偷走的那份里可能带种子）

### 数据模型（新增 3 张表，不动任何现有表）

- `farm_plots` — 地块：`player_id`、`owner_type`（`player`\|`character`）、`owner_id`、`plot_index`、`crop_key`、`planted_at`、`watered_at`、`harvested_at`、`yield_count`
  - **男主的地懒生成**：第一次被访问（你去看/去偷）时才建；只覆盖 `friendships` 里 `status='active'` 的男主（位面崽天然不在内）。
- `farm_inventory` — 背包：`player_id`、`item_key`（`seed:tomato` / `crop:tomato` / `dish:starlight_mousse` / `dish:starlight_mousse:上品`）、`count`
  - 这是产品里**第一个真正的背包**（此前探索捡到的只是 `player_facts` 文本）。先只服务农场，不扩散。
- `farm_events` — 事件流水：`player_id`、`character_id`、`type`（`sow`/`water`/`harvest`/`steal`/`cook`/`gift`/`npc_harvest`）、`payload` JSON、`created_at`
  - 是「他为什么会说那句话」的账本：失窃数量、被偷次数、送菜记录全在这里，也是朋友圈 contextHint 的事实来源。

静态定义（照 `world/recipes.ts` 的做法，纯数据不进 DB）：`farm/crops.ts`、`farm/recipes.ts`。

## 六、二消引擎怎么复用（唯一要碰「冻结代码」的地方）

现状：引擎在 `world/match2.ts`，头部注释就写着「纯逻辑，前端直接复用」「无失败：步数用完/任意分数都出成品，分数只决定品质」——正是料理要的。但**块类型、分值、权重写死了修仙五行**（`TILE_SCORE` / `TILE_WEIGHTS` 按 `TileType` 联合类型硬编码）。

**做法**（星落：重做也行）：
1. **参数化块定义**（`types` + 每块分值/权重作为入参数据），引擎搬到共享位置 `apps/server/src/lib/match2.ts`；`world/match2.ts` 留一行 re-export（冻结代码只改一行）。
2. 若参数化过程中发现耦合太深，就在 `farm/` 里**重写一份**引擎，但**沿用同一组权重与分值**。
3. **块数保持 8 块**：引擎注释里有实测结论——纯 5 种基础块时连锁会爆炸（单步最高 70 层），凑到 8 种（5 基础 + 3 加成）才压成「偶尔大爆发」（p50 约 7 层、max 约 555）。料理盘面沿用同样的 5+3 结构与权重分值，只换名字。

料理盘面块名（草案，待你改）：

| 位 | 修仙（现） | 料理（草案） | 分值 / 权重（沿用） |
|---|---|---|---|
| 基础 5 | 金 木 水 火 土 | 星光果 / 云顶米 / 晨露菜 / 烈火椒 / 岩纹肉 | 各 1 分 |
| 加成 1 | 灵石 | 老火高汤 | 3 分 |
| 加成 2 | 丹炉 | 猛火 | 2 分 |
| 加成 3 | 仙晶 | 秘制酱 | 8 分（稀有） |

✅ **品质阈值已按料理盘面重校准**（不再是衍生世界那套 200/280/380）。做法：同一套权重下用「贪心玩家」（`lib/match2.greedyPlay`，每步挑消得最多的）跑 40 局 7×7 / 12 步取分位 —— **p25 252 / p50 314 / p85 428，max 506，均值 323**；随机合法交换（真人下限）五局只有 138~308。最终取 **下品 <250 / 中品 ≥250 / 上品 ≥320 / 极品 ≥430**（贪心打法约 15% 能到极品），写在 `farm/kitchen.ts` 的 `KITCHEN_QUALITY_TIERS`。真人数据攒出来后用 `lib/match2.calibrateTiers()` 重跑一遍即可。

前端也能直接复用同一份纯逻辑（注释里就是这么设计的）→ 本地即时反馈 + 服务端结算校验。

## 七、男主侧：被偷之后（按性格，不指控玩家）

- **只写进记忆**：`farm_events` 记一笔失窃（数量 + 次数），并写一条记忆（`source='farm'`）：「他院子里的番茄少了三个」。**不进任何数值关系**（产品没有好感数字）。
- **按行程概率发朋友圈**：他行程变更时累积意愿、摇骰子决定发不发（走 `proactive` 既有机制），当天的某个时刻他自己发出来——不是秒发。
- **只说"少了"，不说"是你"**：进模型的只有事实，永远没有"是玩家"。语气按性格分档（用现有人设 + `drive` 推，或懒生成一次落 `character_data`）：

| 档 | 反应 | 举例 |
|---|---|---|
| 粗心型 | 自我怀疑 | 「可能是我自己记错了……昨天真有五个吗」 |
| 多疑型 | 陈述事实、不下结论 | 「我数过。就是少了。」 |
| 腹黑型 | **栽赃**第三方 / 半真半假暗示你 | 「隔壁那家伙最近总在我院子附近晃」/「你要是来过，我也不怪你」 |
| 直球型 | 当面问你但不明说 | 「你今天……有没有路过我那儿？」 |

- 玩家可以回应：评论他这条朋友圈 / 发短信嘴硬否认 → 他信不信按性格（文案分支，不落数值）。
- **P2.5 备选（先不做）**：连续偷同一个人 → 升级成短信质问 / 下次约会当面提 / 搭篱笆降低收益。星落本轮定的是"只进记忆 + 行程概率发朋友圈"，上面这些先记着，不做。

## 八、料理

一次做饭：选菜谱（食材需求）→ **二消盘面（步数 = 火候）** → 分数 → 品质（四档：下品 / 中品 / 上品 / 极品，**不失败**）→ 出菜品。

- **菜是不是模型现场编的**——第一轮离线实测已跑（第十四节），结论是能做，但**必须程序侧喂随机性**，否则菜名会模板塌缩。
- 菜谱来源：初始几道 + 收成解锁 + 专属作物解锁（他最爱那道）。
- 菜品的去处：① 短信发照片给他看 ② 约会时带过去 ③ 塞进信箱当礼物（接上 `UNIMPLEMENTED_FEATURES.md #5 随信礼物` 那个没做完的 TODO）④ 摆自己院子里晒。
- **专属口味**（建议做）：同一道菜不同男主反应不同——把「知道他爱吃什么」变成长期目标。

## 十二、明确不做

- 不做：作物枯死、虫害、体力条、仓库上限、排行榜、每日签到压力、氪金加速、男主之间互偷、偷位面崽的菜、**任何人偷玩家的菜**。
- 不做：主线数值好感；给展示型状态自动衰减；把农场做成「资源管理游戏」。

## 十三、离线验证计划

- 纯函数 + 确定性种子 + 单测（照 `world-*` 的做法）。
- **文案不能靠「看一条觉得还行」**：用真实男主数据跑多次采样，检查——像不像他、**有没有说破玩家**、会不会重复、会不会写成农场公告。
- 二消参数化后，用衍生世界的旧用例回归，确保分数/连锁分布不变。
- 全程不碰线上库；上线前只新增表，不改现有列。

## 十四、离线实测第一轮：gemma 能不能根据消除结果编出料理？（2026-09-25 已跑）

脚本：`apps/server/scripts/ab-farm-cook.ts`（可复跑：`npx tsx scripts/ab-farm-cook.ts 3`），原始结果：`scripts/ab-farm-cook-out/run-*.json`。
做法：**用真实二消引擎**跑 5 局（12 步 / 7×7，随机合法交换）→ 把"消掉了什么、连锁几层、多少分、什么品质"喂给 gemma → 要它编出这道菜；同时测了食材自由填 vs schema enum 钉死两种；最后用**真实沈星回人设**测他吃到菜的反应。

**做得到的（都过）**

- JSON 成功率 30/30、**零截断**、零乱码、菜名零英文、15/15 全不重复。
- **食材合法性满分**：自由填也 **0 次编出盘面上没有的食材**（75/75 命中）；消除量 top2 的食材覆盖 **15/15**。→ 不需要靠 enum 兜底也成立。
- 品质→卖相的对应是通的（极品配"讲究的搭配"、下品没敢吹）。
- **男主反应非常可用**（沈星回真实人设，且他不擅长的正是"做饭"）：
  - 极品：「看起来很漂亮……嗯，尝过了。味道像是在吃一块落下的星光，谢谢。」
  - 下品（糊饭）：「嗯……很有挑战性的味道，辛苦了。」（**照样捧场，不打击玩家**——正是恋爱产品要的）

**做不到的 / 必须程序侧补的（四个问题）**

1. **菜名模板塌缩**：15 个菜名里 14 个是「星X烩饭 / 晨曦烩饭」，同一个盘面连跑三次只换词（绯红岩纹烩米饭→烈焰星芒炖肉饭→烈焰星芒熔岩烩饭）。它抓住了"星光果"的"星"，然后所有名字都套这个模子。→ 对策：**程序侧喂随机性**（从意象词池随机给 2~3 个词让它组合），纯 prompt 约束治不了塌缩。
2. **形态单一**：几乎全是"饭/粥"（因为盘面有云顶米），没有甜点、汤、饮品的分布。→ 对策：**做法形态由加成块决定**（高汤多→炖/汤、猛火多→炒/烤、秘制酱多→凉拌/酱汁、无加成→家常），把"这一局允许的形态"作为硬约束喂进去。
3. **品质区分弱**：下品也编出「晨曦谷物烩蔬」这种体面名字，没有"翻车感"。→ 对策：四档文案要求写死（下品＝朴实/将就/形状散了；极品＝讲究/仪式感）。
4. **起手句重复 + 越界词**：极品反应三次里两次以「看起来很漂亮……」起手、下品三次全是「很有挑战性」；另有一次输出文本里出现了「玩家」字样。→ 对策：禁词表进 prompt + 把"最近 3 次用过的起手句式"喂进去禁止复用（或后处理检测重复起手直接重生成）。

**结论**：这一步**技术上可行、可以进 P3**；但「看起来像不像人编的」取决于程序侧给的随机性与形态约束，不能指望模型自己变花样。
