# 卦象任务系统设计（草案）

> 用《易经》起卦作为任务生成的结构骨架。周易卦象层定"世界调性 + 剧情弧线"（本卦定调性、动爻定变数、变卦定结局、互卦定暗线）；纳甲层定"场上有谁 + 谁跟谁什么关系"（六亲/世应/六神）。
> 状态（2026-08-15）：资产抓取+校验完成、纳甲排盘完成（纯查表 + 60甲子 mod）、端到端流程就绪（scripts/simulate_divination.py）、术语白话化验证通过。**TS 版已接入生产**（`apps/server/src/lib/divination.ts` 纯查表+60甲子mod + `hexagram-prompt.ts` 卦象/纳甲渲染层，4096 组对拍逐字一致）、**worldgen 已迁卦象驱动**、**任务已迁新引擎**（`scene_sessions` + `scene_type='mission'` + 数值判定完成）、**玩法 roll + 世界观基调 + 命名卡已接入生产**（`rollGoal`/`rollTheme`/`rollWorldCards` → `mission.worldgen` prompt 注入 `{{goal_guide}}`/`{{theme_guide}}`/`{{world_cards}}`）。待：旺衰生克层、玩家摇卦交互（阶段4）。

## 一、现状摸底（2026-08-14）

### 世界任务 worldgen 现状
- `mission.worldgen.txt` 纯 LLM 自由生成（temperature 0.9），只有概念约束（"失去价值但被珍藏的物品""执念"），无结构骨架。
- LLM 在自由空间坍缩到高频模式 → 任务趋同。
- 防重 = 单任务互斥（同时只持有一个 world 任务，`status IN ('available','active')` 即 409），**无 used 标记、无主题分布控制**。

### 已有字段 vs 卦象四层

| 卦象层 | 对应叙事层 | 现有 worldgen 字段 | 状态 |
|--------|-----------|-------------------|------|
| 本卦 | 主线调性 | `tone` | 已有，LLM 自由定 |
| 动爻 | 转折/变数 | `twist_seed`、`world_tension` | 已有雏形，无"时机"维度 |
| 变卦 | 结局状态 | —— | **缺失**（新增 `ending_state`） |
| 互卦 | 隐藏暗线 | —— | **缺失**（新增 `hidden_thread`） |

关键发现：变卦、互卦对应的两个叙事层（结局弧线、隐藏暗线）是现有 worldgen 缺失的。这是本设计的真实落点——不是重写现有字段，是补空。

### dramatic_potential 现状
- 是 `backstory_milestones` 角色卡字段（`high`/`medium`/`low` 静态标签），用于角色任务选里程碑（优先 high）。
- 属于角色任务，不是世界任务。卦象的"动爻"给的是世界任务的**转折结构**，与 dramatic_potential 的"张力"语义相通但机制不同。

## 二、核心思路

起卦 → 卦象结构（本/动/变/互）+ 纳甲关系（六亲/世应/六神）→ 注入 worldgen，让两层叙事元素由卦象推导，而非 LLM 自由发挥。

**周易卦象层**（世界调性 + 剧情弧线）：
- 本卦（卦名/卦德）→ 世界调性（革=变革、蒙=蒙蔽、未济=未成）
- 动爻（爻位+爻辞）→ **剧情扣子**（悬念/伏笔）：爻位定扣子扣在哪个阶段，爻辞定扣子性质
- 变卦（本卦+动爻唯一推出）→ **结局状态 = 任务目标**：推动世界从本卦局面走向变卦局面
- 互卦（本卦中爻重组）→ 隐藏暗线（温馨 / 意难平）

**纳甲层**（人物关系网）：
- 六亲 → 谁敌谁友、谁靠山谁对手（见第六节）
- 世应 → 谁是"我"（玩家）、谁是"对方"（任务核心对象）
- 六神 → 扣子的性质色彩（吉庆/口舌/暗昧/凶险…）

### 变卦的双重身份（关键）
- 本卦 = 世界现状（困境未解的局面）
- 变卦 = 目标局面（困境化解后的局面）
- 任务 = 推动世界从本卦走到变卦
- 完成判定 = 数值系统：困境浓度（`stats_config` 初始值）降至目标态（`target`）即变卦达成，由 `judgeStatsAndAmbient` 逐轮判定
- 统一关系：**困境浓度达标 = 变卦达成**；结局的"达成/未达成"即变卦的两个局面，收尾与目标是同一件事的两面。

> 架构演进（2026-08-14 星落拍板）：早期"回收物品 + 执念了却"的完成框架已废弃——"不预设了，现在都有数值系统了，再非要用回收来判定任务完成就很奇怪了"。改为：应爻=任务核心对象（非执念持有者），妻财=所求之物（非强制物品），完成=困境浓度→目标态的数值变化（`stats_config` 的 target 值）。

### "不重复"的两个正交机制
- **结构层**：64 卦 × 动爻组合 = 有穷种子，保证主题分布均匀（不塌缩）。
- **内容层**：被占者（上下文）不同则变易，保证实例无穷变化。
- 分工：卦象做主题调度器，上下文做实例生成器。

### 内在因果
变卦 = 本卦 + 动爻**唯一推出**（不是再抽一次）。任务结局被主线+转折机械推导，任务有了"一个卦象的一次展开"的自洽性，而非三个随机元素的拼凑。

### 世界观基调 + 玩法（新增随机维度，2026-08-15 接入生产）

卦象层（本/动/变/互）和纳甲层（六亲/世应/六神）解决"调性/弧线/关系"的结构骨架，但**玩什么**（打一场？查个案？找个东西？）和**在什么风格的世界里玩**（仙侠？都市？）仍是 LLM 自由发挥的空缺。补两个确定性随机维度：

**世界观基调（第一层，12 类）**：古风/仙侠/民国/都市/乡村/西幻/科幻/日式/灵异/末世/悬疑/二次元（参考网文/无限流副本分类）。`rollTheme(playerId, seq)` 确定性 roll（同 playerId 洗牌 + seq 切块，连续生成轮换不重复）。基调指导整个生成：氛围、NPC 设定、命名风格（12 套地名+职业分库，见 `theme-name-pools.ts` / `name-pool.ts`）。渲染 `{{theme_guide}}`。

**玩法（第二层，5 种）**：战斗/寻物/破案/和解/守护。`rollGoal(playerId, seq)` 同样确定性 roll。玩法是任务主线，写进 briefing/mission_hook，输出 `mission_goal`（"玩法——具体目标"）。渲染 `{{goal_guide}}`。

**五个关键约束（2026-08-15 多轮迭代定稿）**：
1. **去具体例子**：玩法 guide（`GOAL_GUIDES`）只写方向约束 + "写清什么"，不塞样板例子——星落指出"例子会收窄 LLM 输出范围"，去掉后战斗威胁从"讨债/强占"套娃扩到"劫掠物资/羞辱围攻"等多样化人祸。
2. **威胁跟基调走**：战斗/守护的"威胁形态"不硬编码"人祸 vs 妖魔鬼怪"，跟着世界观基调走——灵异出厉鬼、都市出人祸、西幻出魔力、仙侠出灵力。星落原话"看世界观吧？仙侠和日恐啥的出现幽魂也能理解？"
3. **数值降级为可选进度**：`stats`（必填数值浓度）→ `progress`（可选进度名，留空则纯玩法驱动，任务完成以玩法为准，不以数值为准）。
4. **困境要能被玩法化解**：困境（`world_tension`）的出口就是这一局的玩法——玩家用玩法去帮，困境就顺着被推动。别让困境和玩法各说各话（"去病意象"的配套：困境与玩法分开 roll，不咬合就两张皮脱节）。
5. **对手必需性由玩法定**：战斗玩法压的就是一个具体对象，`renderGoalGuide` 对战斗显式要求「正在害人的对象必须作为 world_npcs 里 role=对手 的 NPC 出现」——战斗没对手就穿帮；其他玩法（寻物/破案/和解/守护）对手可有可无，不受卦象官鬼有无限制。

> 玩法演进史（供追溯）：自由选 → 六亲推导（遵循度 11/12 但战斗 0 次、固定日期旬空偏置）→ 确定性 roll（`rollGoal`，64 卦分布均匀、战斗恢复）。六亲推导玩法整套删除（`LIUQIN_GOAL`/`leadLiuqin`），旬空渲染保留（只删"用旬空推导玩法"信号）。

## 三、起卦体系（2026-08-14 修正：统一为纳甲筮法）

### 体系修正（关键）
- **摇铜钱（掷三枚铜钱六次）= 纳甲筮法的起手**。
- 早期方案（上卦 `r1%8`、下卦 `(r2+时辰)%8`、动爻 `(r3+时辰)%6`）是**梅花易数**（数字/时间起卦、先天八卦数），与摇铜钱是两套不同的占卜体系，不应混用。
- **已统一**：起卦用摇铜钱（纳甲），梅花 `r%8` 方案直接废弃。既然起卦落到纳甲，六亲/世应/六神就该跟着起卦一起推演，不分期（这些全是短标签非长文本，注入成本低，没有"信息量稀释"的顾虑）。

### 铜钱法（三枚铜钱掷六次）
- 约定：背 = 3（阳）、字 = 2（阴）。
- 三枚铜钱之和定一爻：

| 三枚组合 | 和 | 爻性 | 记 |
|---|---|---|---|
| 三背 | 9 老阳 | 阳爻，**动** | ○ |
| 两背一字 | 8 少阴 | 阴爻，静 | |
| 一背两字 | 7 少阳 | 阳爻，静 | |
| 三字 | 6 老阴 | 阴爻，**动** | × |

- 六次从下往上排，得本卦六爻阴阳 + 动爻集合。
- 每爻动概率 = 1/4（老阴 1/8 + 老阳 1/8），天然 **0-6 个动爻**（旧方案恰好一个已废弃）。

### 推演两层一起出（纯函数/查表，不交 LLM——LLM 算卦常错）
- **周易卦象层**：变卦 = 翻转所有动爻；互卦 = 第 2/3/4 爻作下卦、第 3/4/5 爻作上卦。
- **纳甲层**：见第六节排盘。

### 随机源（种子）
- 玩家摇卦的随机性来自玩家操作本身（"灵"：触发时刻毫秒 / 心念）。
- 时辰仍进种子（"命"：天时，玩家控制不了）——纳甲里天时的落点是**日干支定六神、月建日辰定旺衰**，不是早前梅花的"时辰%8"。
- 确定性 hash 保留（可复现调试），但正式路径以玩家摇卦为准。

## 四、架构决策（已定）

### ① 卦象资产：尽量全
64 卦静态对照表，能加的都加：卦名、卦德、卦辞、六爻爻辞（384 爻）、大象（象传）、彖传、文言（乾/坤）、哲学含义、名家解卦（王弼、程颐、朱熹等）。
LLM 只负责把卦德/卦义"翻译"成具体世界，卦象文本本身是领域资产，不交 LLM 现编。

### ② 动爻 = 剧情扣子
落地为现有 `twist_seed` 字段，但内容由动爻推导，不再 LLM 自由想：爻位定扣子扣在哪个阶段，爻辞定扣子性质；不强制定义"任务环节"，保持"伏笔、合适时机自然引出"。

渲染补强（2026-08-15）：动爻渲染六亲白话化（「第3爻（妻财：所求之物/情感对象）动」）+ 点明「动爻落在哪个六亲，扣子就扣在哪个关系上，把转折落成『谁和谁出了什么事』的具体人际变故，别只停在物件层面」。起因：gemma 接爻辞只接得住「车子坏了一个轮子」（物件），接不住「夫妻反目」（人际），补后同一卦扣子从「坏车轴」抬到「长辈陈年旧怨」。

### ③ 变卦 = 预设结局 + 任务目标
- 新增字段 `ending_state` 存"预设结局"（叙事弧线的收尾调性）。
- 同时作为任务目标（见"变卦的双重身份"）。
- 与现有评级（evaluateWorldMission：玩家表现）不冲突——评级评"玩家玩得怎样"，变卦定"故事本该走向哪"。

### ④ 被占者 = 玩家 或 角色
- 世界任务：给玩家起卦（玩家是发起者/主角），在 worldgen 之前。
- 角色任务 / NPC 任务：给对应角色起卦（角色是主角）。
- "被占者不同则变易"的语境依赖 = 卦象解读往被占者身上靠。

### ⑤ 种子成分（循环依赖）
- 玩家 ID、起卦时辰、角色 ID、任务相关成分，能加都加。
- **循环依赖**：missionId 生成后才存在，起卦时拿不到 → "任务相关"只能落在生成前可得的量（`quest_type`、该玩家任务序号等）。
- 世界任务若"给玩家起卦"（worldgen 前），任务核心对象尚未生成，角色 ID 天然缺失；只有角色/NPC 任务或"给角色起卦"时角色 ID 才进种子。

## 六、纳甲层（人物关系网，不分期）

> 星落提示（2026-08-14）：四层（本/动/变/互）解决世界调性与剧情弧线的趋同，但**人物关系**（谁敌谁友、谁靠山谁对手）仍是 LLM 自由发挥的空缺。纳甲正好把这层也机械化，随起卦一起推演。

### 排盘（纯查表 + 60甲子 mod，不爬、不硬算）
排盘规则全是固定口诀，硬编码查表即可，**不需要抓网页、不需要复杂算法**：

| 排盘项 | 规则 | 来源 |
|---|---|---|
| 纳支（六爻地支） | 纳甲歌：每卦六爻纳固定地支（如坎内寅辰午、外申戌子） | 固定查表 |
| 卦宫五行 | 八宫卦序：乾兑金、离火、震巽木、坎水、艮坤土 | 固定查表 |
| 世应 | 世应歌：本宫六世、一世/二世/三世/四世/五世、游魂、归魂各有固定世爻位 | 固定查表 |
| 六亲 | 以卦宫五行为"我"，各爻地支五行生克定（生我父母/我生子孙/克我官鬼/我克妻财/同我兄弟） | 固定生克规则 |
| 六神 | 日干起（甲乙青龙→丙丁朱雀→戊勾陈→己腾蛇→庚辛白虎→壬癸玄武），初爻→上爻固定顺序循环 | 日干查表 |
| 干支纪日 | 60 甲子循环：已知基准日 + 天数差 mod 60 | 唯一随日期变的部分 |

### 六亲 → 叙事角色映射
以卦宫五行为"我"，各爻地支五行定六亲，天生就是"户口本 + 敌友"：

| 纳甲 | 五行关系 | 落成任务里的谁 |
|---|---|---|
| 世爻 | 我 | 玩家 |
| 应爻 | 对方/所问 | 任务核心对象 |
| 妻财 | 我克 | 所求之物/资源/情感对象 |
| 官鬼 | 克我 | 对手、不信任、困境人格化（敌） |
| 子孙 | 我生（克官鬼） | 解厄贵人、福神（友） |
| 父母 | 生我 | 靠山、庇护者、长辈 |
| 兄弟 | 同我 | NPC 同伴 / 竞争者 |

### 附加价值：旺衰生克（已做）
动爻落在哪个六亲 → 剧情扣子扣在哪个关系上；官鬼旺则对手强、子孙旺则有解。旺衰由月建/日辰五行 vs 爻五行定。

实现（2026-08-15）：`yueJianOfDay()`（12 节气近似定月建，误差 ≤1 天）+ `wangShuaiOf()`（月建权重高 + 日辰权重低，旺相休囚死口诀白话版）+ `liuQinWangShuai()`（六亲各爻取最旺档）。渲染成「力量对比（旺衰）」注入 `renderNajiaLayer`：官鬼旺→对手势大、子孙旺→有解贵人得力，妻财/父母/兄弟同理白话。日辰干支本就已算（`ganZhiOfDay` mod 60），只补了月建这一块。

### 术语白话化（关键，已定）
- **问题**：gemma 作为国外小模型，对"官鬼/妻财/玄武/朱雀/世应/纳支"这类玄学术语理解力不足，即使配白话释义也优先忽略，术语本身成为噪音。
- **方案**：注入 prompt 时，**纳甲术语全部替换成白话叙事语言**，不出现术语原词。理解前置到数据层，gemma 只做翻译不做理解。
  - 官鬼 → "对手/压力/困境/不信任"；妻财 → "所求之物/资源/情感对象"；兄弟 → "同伴/竞争者"
  - 玄武 → "暗昧隐秘"；朱雀 → "口舌是非"；勾陈 → "迟滞拖延"；白虎 → "凶险冲突"；腾蛇 → "缠绕不安"；青龙 → "吉庆顺遂"
  - 世爻 → "玩家自己"；应爻 → "任务核心对象"
- **验证**：同一卦（山火贲 3 动爻）术语版 vs 白话版对比，白话版六神六亲真正落进剧情（"口舌是非"→执念者低声咒骂指责玩家、"暗昧隐秘"→秘密喂养灵魂、"对手压力"→玩家被当阻碍完美的污点），术语版六神几乎没进剧情。

## 七、玩家摇卦（交互，已定）

> 星落提议（2026-08-14）：让玩家自己摇卦，参与感 + 省随机数 + "天生和玩家的灵感相关"。

### 动机
- 参与感/主体感：玩家亲手摇出的卦"是我的"，比后台 hash 的"天注定"更有代入感。
- 玄学自洽：占卜本就"心动则卦动"，摇卦那一刻的心念注入随机性（"天人感应"）。
- 省随机数：玩家的操作就是随机源。

### 方案
种子 = 玩家ID + 时辰（天时，命）+ 玩家触发时刻/心念（灵）。时辰仍进种子——天时是"命"，玩家控制不了；玩家摇出的"数"是"灵"。

### 已定（2026-08-14 星落拍板）
- **不重摇**：一卦不二占。摇到什么认什么，禁止重摇（否则"诚心摇卦"虚化 + 催生刷签功利玩法）。
- **形式**：摇铜钱（三枚铜钱视觉），一键触发，好玩直观。
- **吉凶无关**：卦辞的吉凶是"世界困境的浓度"，不是玩家运势——凶爻=世界困境更深，吉爻=困境较轻/有解。任务与吉凶无关，玩家不会被卦辞"吓到"。

### 解卦规则（朱熹《易学启蒙》，星落原话"变得少了看变爻，变得多了看不变"）
扣子永远落在少数派：

| 动爻数 | 扣子看谁 | 落点 |
|---|---|---|
| 0（静卦） | 本卦卦德 | 局面稳定，扣子藏在卦德/互卦暗线 |
| 1–2 个 | 动爻爻辞 | 看"变"——转折点在哪 |
| 3–6 个 | 静爻爻辞 | 看"不变"——大势动荡时坚守什么才是关键 |

### 摇卦交互叙述
- **摇一次 = 出一爻**（三枚铜钱掷一下），**摇六次 = 六爻成卦**。
- 起卦 = 摇六次铜钱，每摇一次得一爻，从下往上排成卦。
- 【一键摇】默认：点一下铜钱连滚六次，六爻逐一出齐成卦（快、好玩直观）。
- 【逐爻摇】可选：点六下，每下一爻，看清每枚铜钱正反（仪式感、慢）。

## 九、任务场景 NPC 认知（运行时注入，2026-08-15 定稿）

> 场景对话（`scene_sessions` + `scene_type='mission'`）阶段，每个演员（男主 + 世界 NPC）的 prompt 如何组装、谁知道谁、谁知道什么。核心原则：**代码判断角色身份逐人注入，不写「若你是……就……」让模型自己猜；role（六亲关系）对玩家/男主隐藏，但 NPC 自己要按定位演。**

### 认知矩阵（最终状态）

| 角色 | 自己是谁 | 世界困境 | 任务目标 | 玩家是谁 | 男主是谁 | 任务 NPC 名单 | 六亲关系（谁贵谁敌） |
|---|---|---|---|---|---|---|---|
| 男主 | ✅ 主城 NPC + 降临身份 | ✅ | ✅ | ✅ | ✅（自己） | ✅ 名单 + 人设 | ❌ 隐藏（靠剧情推理） |
| 任务 NPC | ✅ persona + role 定位 | ✅ | ✅ | ✅ | ✅ | ✅（互相认识） | ✅ 自己的定位（角色视角，不用剧作词） |

### 注入机制（scene-wiring.ts）

**共用规则 `scene_rules`（所有演员都看得到）：**
- 来帮助这个世界的人（玩家身份，昵称指代，不用「玩家」）
- 同行的同伴（男主身份 + 元认知「是主城的 NPC，和玩家一起降临，降临身份是——」）
- 任务目标 + 开局情境
- 这是任务世界（玩家定位：降临到此、来帮助这个世界走向目标态）

**逐人 `stance`（代码按角色类型分发，拼进各自的 scene_rules）：**
- **男主**：`【任务世界的这些人】` 名单（name + persona，**不含 role**）+「你是和玩家一起从主城降临的 NPC 同伴，陪玩家推进这件事」。
- **任务 NPC**：按 role 映射成角色视角定位（`roleStance`）——任务核心对象=被帮助的人 / 贵人=主动帮 / 靠山=关键帮 / 对手=不信任 / 竞争者=争同件事 / 所求之人=要找的人。role 缺失按普通居民兜底。

**六亲关系隐藏**：role 标签（贵人/对手/靠山）不注入 character_card（不剧透谁敌谁友），但任务 NPC 通过 stance 知道自己的定位；男主只知道名单 + 人设，不知道 role。

### 官鬼释义软化（2026-08-15）

官鬼（对手）叙事释义 `对手/压力/病症/阻碍` → `对手/压力/病症/不信任` → `对手/压力/困境/不信任`——对手不预设「使绊子/阻碍」，可以只是「不信任这些外来者」（星落原话：对手不一定要使绊子，可以只是"不信任这些人"）。「病症」去病意象改「困境」（星落拍板：去掉第一层病意象、留第二层困境框架）。落在 `divination.ts` 的 `LIUQIN_CN`（生效）+ `LIUQIN_MEANING`（死代码对齐）。

### 代词清洗

- accept 落库时 `descend_identity` 的「你」→ 玩家昵称、「他」→ 男主名（对演员 prompt 第二人称「你」=演员自己，第三人称指玩家/男主处一律用名字，消除歧义）。
- scene-wiring 注入时兜底 `replace(/你/g, 玩家昵称)`、`replace(/他/g, 男主名)` 防旧数据漏网。
