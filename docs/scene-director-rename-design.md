# v2 场景引擎改造：点名版导演（Draft）

> 状态：**已投产（点名版）** · 可随时回退旧导演
> 起因：床戏高频出现「玩家发话后该轮无任何输出/没人理」（空轮），且旁白乱加
> 日期：2026-08-08

---

## 〇、接口现状（新旧 API 标注）

> ⚠️ 点名版已通过 **DB 开关** 接管了全部旧路径，旧路径本身仍被前端调用、仍是生产入口。

### 旧 API（生产在用的路径，内部已被点名引擎接管）
前端实际请求的仍是这些 `/scene/*` 路径（**未废弃、勿删**——是生产入口，走快照即得 DB 开关选中的引擎）：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/scene/start` | 开始约会（返回新/复用会话） |
| POST | `/api/scene/:sessionId/advance` | 推进一轮（带玩家消息） |
| POST | `/api/scene/:sessionId/continue` | 无消息推进（玩家点「继续」） |
| POST | `/api/scene/:sessionId/retry` | 重试本轮 |
| POST | `/api/scene/:sessionId/undo` | 撤销上一轮 |
| POST | `/api/scene/:sessionId/end` | 结束约会 |
| GET | `/api/scene/:sessionId` | 拉取某轮消息 |
| GET/PUT | `/api/scene/engine` | **引擎开关**（admin only），读/写点名 vs 旧导演 |

- 上述路径的 `advance/continue/retry` 已被 `advanceScene` 的 `opts.engine ?? getSceneEngine()` 接管；当 DB `scene_engine='named'` 时内部跑 `runSceneTurnNamed`（点名版），`='director'` 时跑旧 `runSceneTurn`。
- **前端无感知切换**：改 `/api/scene/engine` 的 DB 值即可在点名/旧导演间即时切换，无需改前端、无需重启。

### 新 API（开发期独立测试路径，**当前非生产入口**）
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/scene-named/:sessionId/advance` | 点名版推进（强制 `engine:'named'`，不推 `director` 事件） |
| POST | `/api/scene-named/:sessionId/continue` | 同上，无消息 |
| POST | `/api/scene-named/:sessionId/retry` | 同上，重试 |
| POST | `/api/scene-named/:sessionId/undo` | 撤销 |
| POST | `/api/scene-named/:sessionId/end` | 结束 |
| GET | `/api/scene-named/:sessionId` | 拉取消息 |

- 这些 `/scene-named/*` 路径直接 `advanceScene(..., {engine:'named'})`，绕过 DB 开关强制点名，SSE **不推 `director` 事件**。
- **现状**：用于独立测试点名版；生产前端仍走 `/scene/*`。二者共用同一 `scene_messages` 表。

> 命名约定提醒（见第二节）：文中「男主」= 能加好友有行程的角色（跨场延续），「路人」= 固定蹲当前地点的 NPC，「旁白」「玩家」各自独立。不用「主角/角色」等含糊词。

## 一、为什么换

现在架构是「导演一次排一整轮分镜（一堆含抽象 intent 的 beats）→ 演员逐个去演」。
这一层抽象既制造了**空轮**（玩家发完没理），也制造了**乱旁白**（纯节奏判断失准）。

改为**导演逐拍点名**：
- 导演每拍只决定「这一下放谁出来」
- 不预写任何人的台词、不翻译抽象意图
- 被点名者用现有演员逻辑（直接看对话续写）生成真实内容

## 二、参与者称呼（星落拍板）

| 词 | 含义 |
|---|---|
| **男主** | 能加好友、有自己的行程（schedule）的角色 —— 跟玩家跨场延续的 |
| **路人** | 固定蹲在当前地点的NPC —— 换地点换一批 |
| **旁白** | 旁白 |
| **玩家** | 星落本人 |

## 三、每轮流程（玩家发一次话 = 一轮）

1. **导演逐拍点名**：点一个、那人演、导演看真实进展再决定下一个。

2. **每拍可用名单（代码逐拍算好，导演只能从白名单挑）**：
   - **第一拍**：男主 / 路人 / 旁白（玩家剔除，无「结束」概念——玩家刚发完言，不能空手结束）
   - **第二拍起**：男主 / 路人 / 旁白 / **玩家**（点到「玩家」= 把话头还给玩家 = 这一轮结束/停止）
   - **不连续锁死**：**上一拍发过言的那个，这一拍剔除**（谁都不能连续登场，含旁白不连续两拍）
   - 旁白是一个普通候选，与男主/路人平等竞争（不每轮强制垫，也不消失）

3. **导演职责（判断，非代码硬规则）**：
   - 玩家跟谁说话就点谁接；玩家对男主说话就点男主
   - （无「连续多点点男主」——已删除，被不连续锁死天然约束）

4. **最大拍数 = 代码锁死 5**（玩家发言后最多 5 拍可见内容）。
   **导演不知道这个数**，只被告知「尽快把话点给玩家收敛」，超出由代码截断兜底。

## 四、强制兜底（代码层）

- **必须是「男主」**（能加好友、有行程）——旁白/路人说了不算，不能靠它们糊弄。
- 触发条件：一轮内玩家发话后，**没有任何男主说过话**就到结束/超拍 → **随机拉一个在场男主出来说一句**，保证「理不了玩家」绝不发生。
- 兜底男主随机即可，唯一目的**别晾着玩家**。

## 五、成本

不预生成所有参与者，被点名者才生成 → 与现状持平或更省。

## 六、离线原型验证（2026-08-08）

**原型脚本**：`apps/server/src/scripts/ps-named-director-proto.ts`
**模板**：`apps/server/src/prompt/templates/scene.namer.txt`
**输入**：session `5e1b56a5`（林溯办公室/床戏）round 115 真实玩家发言「（吻住他，手指缓缓移动）」——即真实发生空轮的那次。只读 DB、跑真实 LLM、**不落库、不影响线上**。

### 结论一：模板必须极简 + 编号表（星落定）
第一版模板（带大量解释、让导演从白名单里选**名字**）跑起来导演**无视白名单乱点**：
- 第2/4拍候选 `[旁白,玩家]`，导演却硬点「林溯」→ 实际落到 `avail[0]`=旁白，意图与实际错位
- 5拍死磕「林溯→旁白→林溯→旁白→林溯」，不把话头还给玩家

**星落判断**：小模型（Gemma 4-26B）指令越少越稳，越解释越乱。改为：
1. **导演职责一句话**：根据聊天记录选择当前应该说话的人。不解释。
2. **可用候选构造成编号表** `{1:玩家, 2:林溯, 3:旁白}`，让它**选数字**（输出 `{pick: 编号}`，integer schema，temperature 0.2）。

**改良后实测**（跑出理想结果）：
```
第1拍 候选[1:林溯,2:旁白] → 选1 → 林溯直接接玩家（第一拍强制有人接✅）
第2拍 候选[1:旁白,2:玩家] → 选2 → 玩家 → 把话头还给玩家，本轮结束✅
男主已发言✅ 空轮消除✅ 2拍就收敛（正合"尽快交还玩家"）
```

### 结论二：硬约束靠代码、不靠导演自觉
「不能连续」「第一拍玩家不可选」等都由**代码每拍算白名单**强制，导演只能从名单里选编号——它想违规都没机会。实测严格按白名单执行。

### 结论三：收敛（把话头还给玩家）光靠提示不够
首次原型里模板已反复写"尽快交给玩家"，导演仍死磕 5 拍。转为**编号表 + 极简提示后自然收敛**（2拍即还）。若日后仍偶发不收敛，可在**代码层**于达到一定拍数/连续 N 拍无玩家时强制把话头交给玩家。

## 七、生产用例批量验证（2026-08-08）

**脚本**：`apps/server/src/scripts/ps-named-batch.ts`
**方法**：从真实生产会话读真实历史对话 + 真实玩家发言，构造 input 跑逐拍点名。只读 DB、真实 LLM、不落库。

### 批量结果

| 用例 | 场景 | 点名序列 | 男主发言 | 空轮 |
|---|---|---|---|---|
| 林溯·办公室床戏 | 单人 | 林溯→旁白→林溯→**玩家** | ✅ | ✅消除 |
| 冷惊尘·家日常 | 单人 | 冷惊尘→旁白→冷惊尘→旁白→**玩家** | ✅ | ✅消除 |
| 方知衡·电竞中心追问 | 单人 | 方知衡→**玩家** | ✅ | ✅消除 |
| 异能局·群戏 | 苏烬+5路人(沈砚/温柚/陆骁/苏渺/季星遥) | 苏烬→**玩家** | ✅ | ✅消除 |

### 验证点全部通过

1. **空轮彻底消除** ✅：4/4 用例第一拍都强制有人接，无一空轮。
2. **不连续锁死** ✅：林溯↔旁白、冷惊尘↔旁白严格交替，代码级无连续。
3. **第一拍玩家不可选** ✅：所有用例首拍候选均无"玩家"。
4. **编号表稳定** ✅：导演全程选数字，严格按白名单，无一越界乱点。
5. **收敛及时** ✅：4 例均在拍数内（2/4/5拍）选"玩家"结束，把话头交还给玩家。
6. **群戏路人处理合理** ✅：异能局 5 路人都进候选，但导演首拍选男主苏烬接（玩家正跟苏烬撒娇）；未强行拉无关路人进场。
7. **角色格调保留** ✅：苏烬"队长在姐姐面前只想当小朋友"、方知衡学者式剖白、林溯床戏反应，均贴人设，无现架构的脱节感。

### 观察（非问题）
- 冷惊尘例旁白第2/4拍稍偏多（5拍2旁白），但均为对"玩手机/安静"氛围的合理渲染，非乱加；床戏旁白（高潮后）恰如其分。

## 八、接生产待办（下一步）

逐拍点名已验证健康，接生产需：
1. 在 `scene-wiring.ts` 的 advance 路径里，用「逐拍点名循环」替换 `runSceneTurn` 的 `runDirector`（一次排 beats）段；循环骨架/不连续/去重/旁白/兜底/落库逻辑全复用现有 `runSceneTurn`。
2. namer 调用：`callType='namer'`，integer schema，temperature 0.2；可用候选按编号表传入。
3. 生成只在「被点名者」身上发生（不预生成），维持与现状持平的成本。
4. 兜底（必须男主）保留在代码层。
5. 确认是否保留 `runSceneTurn` 的老导演分支（灰度切换，便于 AB 对比）。

### 实现方式（星落已确认：现有保留、新 API、输入输出一致）
- `advanceScene` 加可选参数 `opts.engine?: 'director' | 'named'`，**默认 `'director'`（现有行为分毫不变）**。
- 新增 runner `runSceneTurnNamed(input, {onLog, onBeat})`：逐拍点名循环（复用 runActor/runNarration + namer 编号表 + 白名单 + 兜底）。
- 当 `engine==='named'` 时，advanceScene 第 6 步调 `runSceneTurnNamed` 替代 `runSceneTurn`，**其余 600 行（上下文/记忆 build + 落库 + stats + 折叠）完全复用**。
- 新增路由 `scene-named.ts`：复制 `/scene/:id/{advance,continue,retry,undo,end}` 的 SSE 外壳，调 `advanceScene(..., {engine:'named'})`，**不推 `director` 事件**（前端导演已隐藏）。
- 无灰度开关——测完直接切（前端 `/scene`→`/scene-named` 或后端默认 engine 改 named）。

### 一致性保证（记忆/统计/落库自动复用）
- `runSceneTurn` 是**纯函数**：只产出 `{beats, output, statsState}`，内部不做任何落库/记忆折叠。所有持久化（落库、stats 写回、记忆折叠 `runTurnMemoryUpdate`、按轮快照、关系描述更新）都在 `advanceScene` 第 7–9 步由外部统一做。
- 因此只要 `runSceneTurnNamed` 返回的 `result` 形状与 `runSceneTurn` 一致（`{beats, output, statsState, attempts}`），**记忆提取折叠、stats 结算、落库、快照全部自动复用、一行不改**。
- 男主/路人看到的历史拼接格式与现有 `runActor` 一致（`旁白`→`（旁白）xxx`、`男主`→`林溯：xxx`、玩家新话末尾追加），因为点名版复用同一 `advanceScene` 上下文构建 + `conversationSoFar` 实时累加。
- ⚠️ **点名版需自行处理 stats 结算**：现有 runSceneTurn 在逐拍里处理 narration 的 `fn`（调数值函数更新 statsState）。点名版若点名到旁白且需结算 stats，必须在旁白生成时同样执行 stats 函数，避免换引擎丢统计。

## 九、上线方式与一次严重 Bug 修复（2026-08-08）

### 上线方式：DB 开关，运行期可回退（不启服务）
- `advanceScene` 的引擎解析改为 `opts.engine ?? getSceneEngine()`，`getSceneEngine()` 读 DB `app_settings.scene_engine`，缺省 `'director'`。
- 管理端点 `GET/PUT /api/scene/engine`（admin only）读写该开关：
  - 设 `named` → 所有前端 `/scene/*` 推进内部走点名版（前端 URL 零改动、无感知）
  - 设回 `director` → **立即回退旧导演，无需重启、无需改前端**
- 已亲手验证回退链路：切 `director` → SSE 出现 `director` 事件（旧引擎特征）；切回 `named` → 仅 `beat`/`done`。运行期即时生效。
- **切换时机**：每次重启加载最新代码；开关值存 DB 不丢。

### 新引擎 LLM 调用全量落库
- namer / actor / narration 均带各自 `callType`（`'namer'`/`'actor'`/`'narration'`）写 `llm_call_log`（保留 24h），和旧引擎同一条链路，可回查、可复现。
- 排查「云层？」空轮即靠 namer 的 `parsed_json: {"pick":2}` 还原点名轨迹。
- `llm_call_log.session_id` 保持不填（按 callType + 时间段回查即可；星落定，玩家无需知道归属哪个约会）。

### ⚠️ 严重 Bug：玩家第一次发言时空轮（已修）
**现象**：玩家发「（愣了一下，看向他）云层？」后，该轮只有一条旁白，男主方知衡没有回应玩家的话。

**根因**：点名版兜底用 `isOpening`（=「历史里有没有玩家消息」）当门槛。而**玩家第一次发言**那一轮，历史里恰好还没有玩家消息 → `isOpening=true` → 走进「开场无可见输出才兜底」分支；该轮恰有一条旁白（visibleCount=1），兜底被跳过 → 玩家话无人回应。

**修复**：兜底判定改为以 **`hasPlayerInput`（本轮有没有玩家输入）** 为准——只要本轮玩家发了话且无任何男主发言，就强制拉男主回应，不再受「是否开场」干扰。开场轮（无玩家输入）仍用原 visibleCount 兜底开场。

**验证**：用真实 round-2 场景复现：
```
修复前：只有旁白，方知衡不回
修复后：旁白 → 点到玩家收尾 → 兜底触发 → 方知衡补 3 条回应
日志：→ 点到玩家：把话头还给玩家 ≈ ⚠️ 玩家发了话但本轮无任何男主发言，强制兜底拉男主回应 ≈ ✅ 兜底由「方知衡」补出 3 条气泡。
```
已上线（重启生产 + 保持 named）。
