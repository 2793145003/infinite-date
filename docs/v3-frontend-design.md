> 状态：已定稿（2026-08-20 更新：布局从「心动终端桌面图标」改为「虚拟伴侣信息架构 + 全网格首页」）
> 范围：**仅前端**。后端引擎 / 数据模型零改动。版本号 v3 指前端版本。

---

## 0. 一句话

前端 IA + 视觉改版：**布局骨架照搬「虚拟伴侣与记忆空间」，视觉皮照抄「心动终端」**。首页改成 4 列全网格（伴侣卡 / 时钟 / 诗句 / 功能卡全是格子），底部胶囊 dock 5 项，水彩壁纸 + 毛玻璃皮肤。后端不动，新前端直接接现有 `/api/*`。

## 3. 首页全网格（核心定稿）

首页内容区 = **4 列 CSS Grid**。**伴侣卡 / 时钟 / 诗句 / 功能卡，四者全是格子**，用 `col-span / row-span` 表大小，没有特殊元素——格子身份统一、内容各异。

网格之外只有两样：顶部 **header**（位置 + 朋友圈/信箱按钮）、底部 **dock**。这俩是全局框架，不参与拆格。

### 3.1 伴侣卡（形态保持现状，内容可能先变动）

- **形态**：保持现状（头像 + 名字 + 切换 + 关系状态 + 相伴时长），不预先做缩格；8↔4 两态只记为未来降级储备，等真需要腾格时再改。
- **内容**：卡片字段（关系状态 / 相伴时长等）反而可能先调整，优先级高于形态改动。

### 3.2 功能卡池（8 格，可重分）

默认分配：

| 功能 | 格子 | 形状 |
|---|---|---|
| 地图约会（→ 图形地图 SceneMapViz） | 4 | 2×2 大卡 |
| 任务世界 | 2 | 2×1 横条 |
| 场景剧本 | 2 | 2×1 横条 |

新功能进池 = 拆池子里的格，被拆者降权。**格子大小 = 功能当前重要性。**

### 3.3 时钟（格子，形态未定）

占格，具体形态（大数字 / 圆形）等新功能真来、需要腾位置时再定。

### 3.4 诗句（硬编码一句保底，等 API 后替换）

- 现在：硬编码**一句**保底文案占位显示（不做多句轮播）。
- 将来：有了 API 后替换成动态「男主每日一句」（可挂 v2 `moment-scheduler` + `proactive.ts`，后端已有能力）。

## 6. 降级链（框架，细节等真实需求再拍）

首页放不下时，遵循「**关系保底、氛围弹性、功能最后动**」：

1. 先收诗句（并入伴侣卡 / 删）
2. 再缩时钟（大数字 → 圆形 1 格）
3. 最后才拆功能卡池的格

伴侣卡是「关系保底」锚点，形态现在不预设（保持现状），等真需要腾格时再议。

## 9. 邀请码（普通玩家）——独立于 v3，属后端小改动

> 状态：已拍板，暂不实现。v3 前端先在设置里留「邀请好友」入口；后端接口另做，不混进 v3。

- **能力**：普通玩家可生成邀请码邀请好友（当前 `POST /admin/invite-codes` 被 `requireAdmin` 锁死，需新增普通玩家可调用接口）。
- **关系**：各玩各的 —— 被邀请人用码登录后是纯新账号，不记录社交关系、不自动加好友。
- **消耗**：生成 1 个邀请码消耗 **100 权限点**（从 `player_permissions.balance` 扣，走 `permission_transactions` 记账，余额不足则不可生成）。
- **入口**：设置里「邀请好友」，不单独做 app。
